# SmartLock — UART Self-Test

## 1. Призначення

UART self-test призначений для автоматичної перевірки стану апаратних компонентів SmartLock під час запуску прошивки.

Результати перевірки передаються через UART у структурованому текстовому форматі, придатному для автоматичного аналізу.

Самоперевірка реалізується в окремому модулі `firmware/App/self_test.c` та `firmware/App/self_test.h`.

## 2. Взаємодія з драйверами

Драйвери пристроїв надають результати ініціалізації та діагностики через наявні програмні інтерфейси.

Для повідомлення про помилки використовується тип `dev_status_t`, визначений у `firmware/Devices/dev_bus.h`.

Модуль self-test відповідає за:

- отримання результатів перевірки пристроїв;
- формування структурованих UART-повідомлень;
- відображення статусів і причин помилок;
- формування загального підсумку перевірки.

Модуль не здійснює безпосередніх звернень до STM32 HAL, I²C або SPI.

## 3. Статуси перевірки

| Статус | Значення |
|---|---|
| `OK` | Пристрій успішно пройшов перевірку |
| `WARN` | Пристрій доступний, але виявлено відхилення |
| `FAIL` | Обов'язкова перевірка завершилася помилкою |
| `SKIP` | Перевірку свідомо пропущено із зазначенням причини |

## 4. Формат UART-повідомлень

Кожне повідомлення починається з префікса `ST`.

Формат повідомлення про пристрій:

`ST,<device>,<status>,key=value,...`

Формат загального підсумку:

`ST,SUMMARY,<status>,ok=N,warn=N,fail=N,skip=N`

Приклад очікуваного виводу:

```text
ST,START
ST,BMP180,OK,id=0x55
ST,MPU6050,SKIP,reason=module_not_responding
ST,LSM303D,WARN,reason=axis_xy_invalid
ST,W25Q64,OK,id=EF4017
ST,SUMMARY,WARN,ok=2,warn=1,fail=0,skip=1
```

Наведені повідомлення є прикладом формату, а не результатом нового запуску обладнання.

## 5. Формування загального статусу

- Якщо хоча б один пристрій має статус `FAIL`, загальний статус — `FAIL`.
- Якщо помилок `FAIL` немає, але є `WARN` або `SKIP`, загальний статус — `WARN`.
- Якщо всі перевірки завершилися зі статусом `OK`, загальний статус — `OK`.

## 6. Програмний інтерфейс

Модуль self-test передбачає функції:

- `SelfTest_FormatLine()` — формування повідомлення про пристрій.
- `SelfTest_FormatSummary()` — формування підсумкового повідомлення.
- `SelfTest_SetOutput()` — налаштування способу виведення.
- `SelfTest_Report()` — формування повного звіту самоперевірки.

Фактичні сигнатури функцій визначаються файлами `self_test.h` і `self_test.c`.

## 7. Перевірка та інтеграція

Форматування повідомлень передбачається перевіряти на комп'ютері без фізичного обладнання.

Після інтеграції з `App_Init()` потрібно перевірити:

- виведення результатів усіх пристроїв;
- правильність статусів і причин помилок;
- коректність підсумкових лічильників;
- відповідність UART-повідомлень результатам перевірки на стенді.

**Поточний стан:** формат визначено на основі наявних інтерфейсів проєкту та результатів стендової перевірки. Остаточне погодження й інтеграція потребують перевірки.

## 8. Перевірки пристроїв стенда

Перевірки всіх пристроїв стенда виконує модуль `firmware/App/stand_test.c` (`stand_test.h`). Кожна перевірка заповнює `self_test_device_t` і буфер полів і нічого не друкує; рядки формує `SelfTest_Report()` / `SelfTest_FormatLine()`. `StandTest_Run()` викликається з `App_Init()` після налаштування виводу (`SelfTest_SetOutput()`).

Перед `ST,START` виводяться коментар `# SmartLock selftest v2 (LR2)` і інформаційний рядок скану шини `I2C,scan,0x..,...` (у підсумок не входить).

| Пристрій | Поля | Умови |
|---|---|---|
| `UART` | `baud=115200` | завжди `OK` |
| `MPU6050` | `who,a_g,ax_g,ay_g,az_g,gyro_max_dps,t_c` | помилка шини — `SKIP` з `err=<код>,note=GY-521_faulty_FR06_on_LSM303D`; \|a\| поза 1 g ± 5 % або гіроскоп ≥ 5 °/с — `WARN` |
| `BMP180` | `id=0x55,t_c,p_hpa` | поза 15–35 °C / 950–1050 гПа — `WARN` |
| `L3GD20` | `addr,who` | WHO_AM_I на 0x6B, потім 0x6A; невідомий ID — `WARN`; ніхто не відповів — `FAIL,err=nack,addr=0x6B\|0x6A` |
| `LSM303D` | `addr,who=0x49,role=FR06_accel,raw=XXXX,XXXX,XXXX,a_g,ax_g,ay_g,az_g` | \|a\| поза 1 g ± 5 % — `WARN` |
| `W25Q64` | `jedec,size_mbit` | не Winbond — `FAIL,err=bad_id`; інша ємність — `WARN,...,note=not_q64` |
| `OV7670` | `pid,ver,vsync_hz` (кадри за 1 с) | інший PID/VER або немає VSYNC — `WARN`; SCCB без відповіді — `FAIL` з `hint=check_MCLK_D7_PWDN0_RST1` |
| `DHT11` | `t_c,rh,raw,crc=OK` | помилка CRC — `FAIL,err=state,hint=crc`; поза 10–40 °C / 10–95 % — `WARN` |
| `SERVO_PWM` | `freq_hz,pulse_us,note=no_feedback` | не 50 Гц або імпульс поза 1000–2000 мкс — `FAIL,err=state` |
| `GPIO` | `btn=XXXX,lock_b1,door,pir,mpu_int` | знімок входів, завжди `OK` |

Для `FAIL` код причини береться з поля `error` (`err=<код>` додає `SelfTest_FormatLine()`), для `SKIP` — записується в поля.

## 9. UART-команди стенда

Після self-test виводиться довідка, далі `App_Loop()` обробляє команди з USART2 (`firmware/App/bench.c`). Рядки перевірок (`ST,...`) ідуть через вивід self-test, решта — службові рядки `<ТЕМА>,ключ=значення`.

| Команда | Дія | Вивід |
|---|---|---|
| `s` | повний self-test і довідка | `ST,START` … `ST,SUMMARY,...` |
| `i` | скан I2C1 | `I2C,scan,0x..,...` |
| `g` | стеження за входами (вкл/викл), антидребезг 20 мс | `[мс] GPIO,btn=...` |
| `m` | LSM303D ×10 (FR-06), MPU-6050 — якщо відповідає | `ST,LSM303D,...` |
| `b` | BMP180 | `ST,BMP180,...` |
| `h` | DHT11 ×5 з інтервалом 2 с | `DHT,<стан>,...` |
| `j` | JEDEC ID флеш-пам'яті | `SPI,jedec=...,err=...` |
| `f` | стирання/запис/читання останнього сектора W25Q64 | `FLASH,rw=PASS\|FAIL,...` |
| `1` / `2` / `3` | імпульс серво 1000 / 1500 / 2000 мкс | `SERVO,pulse_us=...,freq_hz=...` |
| `a` | діагностика LSM303D (регістри, BOOT, вбудований self-test) | `ACC,...` |
| `c` | OV7670: ID і VSYNC | `ST,OV7670,...` |
| `k` | повільний PCLK камери: CLKRC = 0x1F, повторно — 0x80 | `CAM,slow_pclk=...,clkrc=...` |
| `x` | демонстрація NACK (читання з 0x50) | `I2C,nack_demo,addr=0x50,result=nack` |
| `l` | періодичний трафік ЛР1 (вкл/викл) | `# LR1 loop traffic ...` |
| `?` | довідка | `# commands: ...` |

## 10. Вивід на реальному стенді

Реальний запис UART зі стенда — `docs/lab_2/selftest-log.txt` (з `docs/captures/uart_selftest.sr`). Його зроблено попередньою версією прошивки стенда, тому формат трохи відрізняється від поточного: немає рядка `ST,START`, флеш-пам'ять називалася `W25QXX`, а `SKIP` не впливав на підсумок (там `ST,SUMMARY,WARN` — через `WARN` від LSM303D). Байти I²C-транзакцій і значення полів збігаються; це перевіряє replay-тест `tests/unit/test_stand_test.c`.
