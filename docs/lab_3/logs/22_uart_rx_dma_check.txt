# Стенд SmartLock, Nucleo-F411RE, USART2 115200 8N1 через ST-LINK VCP. Дата: 2026-11-19.
# Прошивка: гілка lab3/uart-rx-dma (коміт 4d43075, у банері git=4d43075) — прийом команд через DMA-кільце
# (виправлення issue #41). Збірка в Docker (stm32-builder, arm-none-eabi-gcc 10.3.1); make build і make test — PASS.
# Перевірка тими самими тестами, що виявили втрати в лозі 20. Команди надсилались ОДНИМ БЛОКОМ,
# без паузи між символами і без повторів (обхід у uart_capture.py вимкнено: --char-gap 0 --quiet 0 --retries 1).
#
# --- 1. Порівняння з логом 20 (main fd23599) ---
# тест                                                    | main fd23599           | lab3/uart-rx-dma 4d43075
# 40 × PING n, випадкова пауза 0,3–0,9 с                  | 31/40, rx_overrun=14   | 40/40, rx_overrun=0
# 81 команда (80 × PING + STATS) після 0,2 с тиші         | 74/81, rx_overrun +11  | 81/81, rx_overrun=0
# 5 × PING n одним блоком під час CAM TEST (×5 кадрів)    | —                      | 25/25, 5/5 кадрів ok
UART rx_overrun=0 cmd_overflow=0 cmd_dropped=0 rx_peak=10
UART rx_overrun=0 cmd_overflow=0 cmd_dropped=0 rx_peak=51
STAT name=camera n=5 min_us=1040432 avg_us=1581410 max_us=1979669
# Під час CAM TEST переривання маскуються на кожен рядок кадру, цикл стоїть 1,0–2,0 с — команди
# все одно приймаються DMA і виконуються після захоплення.
#
# --- 2. Потік команд без пауз (UART flood) ---
# потік 10 команд (81 Б):   PONG 10/10, rx_peak=58
# потік 25 команд (225 Б):  PONG 25/25, rx_peak=186
# потік 50 команд (450 Б):  PONG 42/50, далі ПК → плата нічого не доходить
# потік 200 команд (1892 Б): PONG 43/200, далі ПК → плата нічого не доходить
# Діагностика після зависання (регістри через SWD, st-flash read, без зупинки МК):
#   DMA1_S5CR=0x08020519 (EN=1, CIRC=1), S5NDTR=0x540; USART2_SR=0xD0 (RXNE=0, ORE=0)
#   надіслано ще 30 Б → S5NDTR=0x540 без змін, USART2_SR=0xD0: байти до МК не надходять.
# Плата друкує далі (LOAD/ENV), прийом відновлюється лише після перепідключення USB —
# на будь-якій прошивці (перевірено й на main fd23599). Зависає ST-LINK VCP (версія JTAG 0x21 = V2J33),
# коли ПК пише довгий потік і плата одночасно багато відповідає; прошивка МК тут ні до чого.
#
# Висновок: виправлення усуває втрати і спотворення команд у штатному циклі та під час блокувальних
# операцій. Межа UART flood через ST-LINK VCP — ~380 Б потоку з одночасною відповіддю плати; для
# сценарію UART flood (§6.2) це обмеження стенда, а не прошивки.
