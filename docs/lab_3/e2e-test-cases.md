
# SmartLock — системні E2E-тести

**Платформа:** STM32 NUCLEO-F411RE  
**Архітектура:** Bare Metal / Super Loop  
**Кількість сценаріїв:** 6  

## E2E-01. Швидкі натискання кнопок та антидребезг

**Пов'язані вимоги:** FR-02, FR-09, FR-10.

### Передумови
- SmartLock увімкнений, кнопки та UART працюють.
- Реалізовано програмний антидребезг.
- Доступний журнал подій кнопок і переходів FSM.

### Кроки
1. Перевести систему в `UNLOCKED`.
2. Декілька разів швидко натиснути USER B1.
3. Перевірити, що система коректно переходить в `EXIT_DELAY`.
4. Перевести систему в `LOCKED`.
5. Швидко натискати чотири зовнішні кнопки, вводячи тестовий код.
6. Перевірити зареєстровані натискання та реакцію системи.

### Очікуваний результат
- Одне фізичне натискання реєструється як одна команда.
- Дребезг не створює додаткових символів.
- Повторні натискання B1 не перезапускають таймер.
- FSM не переходить у некоректний стан.
- Код обробляється відповідно до введеної послідовності.

### PASS / FAIL
- **PASS:** немає зайвих команд, дублювання символів і некоректних переходів FSM.
- **FAIL:** виникають дублікати натискань, помилкова авторизація або некоректні переходи.


## E2E-02. Одночасні сигнали PIR та MPU-6050

**Пов'язані вимоги:** FR-05, FR-06, FR-07, FR-08.

### Передумови
- SmartLock перебуває у стані `LOCKED`.
- PIR та MPU-6050 працюють.
- Поріг `TAMPER` узгоджений.
- Доступні UART та журнал W25Q64.

### Кроки
1. Перевести SmartLock у `LOCKED`.
2. Створити рух перед PIR.
3. Приблизно в той самий момент виконати контрольований вплив на макет для MPU-6050.
4. Перевірити події в UART і журналі.
5. Повторити перевірку двічі.

### Очікуваний результат
- Реєструються обидві події: `MOTION` і `TAMPER`.
- Жодна підтверджена подія не втрачається.
- Система залишається в `LOCKED`.
- Для охоронних подій ініціюється фотофіксація або фіксується діагностована помилка камери.

### PASS / FAIL
- **PASS:** обидві події зареєстровані, FSM залишається в `LOCKED`; фотофіксація відповідає PRD.
- **FAIL:** одна з подій втрачена, FSM змінюється некоректно або фотофіксація не ініціюється без пояснення помилки.


## E2E-03. Правильний і неправильний код під навантаженням

**Пов'язані вимоги:** FR-09, FR-10, FR-11, FR-12.

### Передумови
- SmartLock у стані `LOCKED`.
- Працює введення коду чотирма кнопками.
- Доступні UART, журнал W25Q64 та сервопривід SG92R.

### Кроки
1. У стані `LOCKED` забезпечити звичайне фонове опитування датчиків і UART-діагностику.
2. Ввести неправильний код.
3. Перевірити стан засувки та журнал.
4. Ввести правильний код.
5. Перевірити розблокування SG92R і перехід FSM.
6. Переконатися, що без натискання B1 система не блокується повторно.

### Очікуваний результат
- Неправильний код створює `WRONG_CODE`.
- Після неправильного коду система залишається в `LOCKED`.
- Правильний код створює `ACCESS_GRANTED`.
- SG92R переходить у положення `UNLOCK`, FSM — у `UNLOCKED`.
- Фонові задачі не змінюють логіку авторизації.

### PASS / FAIL
- **PASS:** обидва коди обробляються правильно, журнал містить відповідні події, помилкового розблокування немає.
- **FAIL:** неправильний код відкриває замок, правильний не відкриває або виникають некоректні стани/події.



## E2E-04. Затримка 15 секунд за відчинених дверей

**Пов'язані вимоги:** FR-01, FR-02, FR-03, FR-04, FR-13.

### Передумови
- SmartLock перебуває в `UNLOCKED`.
- Геркон визначає `DOOR_OPEN` і `DOOR_CLOSED`.
- SG92R керує демонстраційною засувкою.

### Кроки
1. Відчинити двері макета.
2. Натиснути USER B1.
3. Переконатися, що система перейшла в `EXIT_DELAY`.
4. Залишити двері відчиненими понад 15 секунд.
5. Перевірити, що засувка не заблокувалася.
6. Зачинити двері та дочекатися підтвердженого `DOOR_CLOSED`.
7. Перевірити перехід до `LOCKED`.

### Очікуваний результат
- Після B1 запускається один відлік на 15 секунд.
- Поки двері відкриті, засувка залишається в `UNLOCK`.
- Після закінчення відліку система очікує закриття у стані `EXIT_DELAY`.
- Після підтвердженого закриття засувка блокується без повторного 15-секундного відліку.

### PASS / FAIL
- **PASS:** таймер відповідає `15 ± 0,1 с`, за відчинених дверей замикання немає, після закриття відбувається `LOCK` без нового відліку.
- **FAIL:** передчасне замикання, повторний відлік або відсутність блокування після стабільного закриття.


## E2E-05. Охоронна подія під час операції Flash

**Пов'язані вимоги:** FR-05, FR-08, FR-12.

### Передумови
- SmartLock у стані `LOCKED`.
- W25Q64 доступна для запису.
- PIR працює.
- UART показує початок і завершення Flash-операції або доступні еквівалентні часові позначки.

### Кроки
1. Перевести SmartLock у `LOCKED`.
2. Запустити штатну операцію запису даних у W25Q64.
3. Під час виконання операції створити рух перед PIR.
4. Переконатися за часовими позначками, що сигнал виник під час Flash-операції.
5. Перевірити реакцію SmartLock та журнал подій.
6. Перевірити, що дані Flash залишилися коректними.

### Очікуваний результат
- Система не зависає.
- Подія `MOTION` не втрачається.
- Подія зберігається у журналі після завершення необхідних операцій.
- Інші записи Flash залишаються цілісними.
- Стан FSM залишається `LOCKED`.

### PASS / FAIL
- **PASS:** підтверджено перетин сигналу з Flash-операцією; подія оброблена, журнал не пошкоджений, система продовжує роботу.
- **FAIL:** подія втрачена, журнал пошкоджений або система зависає.

## E2E-06. Перезапуск і цілісність журналу W25Q64

**Пов'язані вимоги:** FR-08, FR-10, FR-12.

### Передумови
- SmartLock працює з W25Q64.
- Реалізовано запис і читання журналу.
- Доступний перегляд записів через UART.
- Перевірка проводиться на низьковольтному лабораторному стенді.

### Кроки
1. Увімкнути SmartLock.
2. Створити декілька подій: `LOCKED`, `WRONG_CODE`, `ACCESS_GRANTED` та інші доступні події.
3. Прочитати журнал через UART і зафіксувати порядок записів.
4. Після завершення запису штатно вимкнути живлення.
5. Повторно увімкнути SmartLock.
6. Прочитати журнал і порівняти записи до та після перезапуску.

### Очікуваний результат
- Раніше записані події залишаються доступними.
- Порядок та ідентифікатори подій не змінюються.
- Пошкоджені або дубльовані записи відсутні.
- Після запуску UART і журнал працюють коректно.

### PASS / FAIL
- **PASS:** усі створені записи збереглися без втрат, дублювання та порушення порядку.
- **FAIL:** записи зникли, пошкодилися, дублювалися або журнал недоступний.
